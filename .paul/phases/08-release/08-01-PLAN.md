    Create `DESIGN.md` in project root. Structure:

    **# SolarDrone — Architecture**

    One-sentence summary of the signal chain.

    **## Design Principle: SynthParamMapper as Canonical Product**

    Explain: the mapper is the stable contract. AdditiveEngine and VisualRenderer are independent consumers of SynthParams. New data sources plug into SpaceWeatherState. New renderers (granular, FM, spatial) plug in downstream of the mapper.

    **## Components**

    For each of 5 components, write:
    - What it does (2-3 sentences)
    - Key files
    - Key decisions (2-3 bullet points)

    Components in signal order:
    1. **DataFetcher** (`src/DataFetcher.h/cpp`) — background thread, NOAA polling, null handling, last-valid cache. Key decisions: launches from constructor (not prepareToPlay), isEmpty() = fallback, JUCE_USE_CURL=1 on Linux only.
    2. **SynthParamMapper** (`src/SynthParamMapper.h/cpp`) — pure function, no JUCE dependency. Key decisions: hybrid mapping (linear base + non-linear at Bz≤-10nT, Kp≥6), l2_amplitude raw (layer_balance applied downstream), just intonation lookup table.
    3. **Interpolator** (`src/Interpolator.h/cpp`) — per-field exponential slew at ~100Hz. Key decision: alpha = 1 - exp(-4.6 / (glide_secs * 100)), 99% convergence in glide_time_secs.
    4. **AdditiveEngine** (`src/AdditiveEngine.h/cpp`) — two OscillatorBanks + Interpolator. Key decisions: control-rate architecture (processBlock sub-blocked at ~100Hz), constant-power crossfade (cos/sin), std::sin() — no wavetable needed (~0.33ms/block).
    5. **VisualRenderer** (`src/VisualRenderer.h/cpp`) — JUCE Component + Timer 30fps, three composited layers. Key decisions: Timer poll (not audio thread push), spectral→particles→lissajous draw order, CriticalSection for thread handoff.

    **## Thread Model**

    Diagram:
    ```
    Background thread (DataFetcher):  NOAA HTTP every 60s → SpaceWeatherState
    Audio thread (processBlock):       read state → SynthParamMapper → Interpolator → OscillatorBanks
    Message thread (Timer 30fps):      poll smoothed SynthParams → VisualRenderer → repaint()
    ```

    **## Extending SolarDrone**

    Two common extension patterns:
    1. **New data source** (e.g., X-ray flux in v2.1): add field to SpaceWeatherState, parse in DataFetcher, map in SynthParamMapper. Zero changes to engine or renderer.
    2. **New synthesis engine** (e.g., granular in v2): implement `GranularEngine` consuming SynthParams. Swap AdditiveEngine in PluginProcessor. Zero changes to mapper.

    **## Parameter IDs (APVTS)**

    Table of all 11 parameter IDs — these are stable API. Do not rename without bumping the APVTS state tag.

    | ID | Type | Range | Default |
    |----|------|-------|---------|
    | volume | float | 0-1 | 0.7 |
    | drone_on | bool | — | true |
    | glide_time | float | 30-300 | 120 |
    | dynamics_range | float | 0-1 | 1.0 |
    | layer_balance | float | 0-1 | 0.5 |
    | stereo_spread | float | 0-1 | 0.5 |
    | harmony_mode | choice | Just/Equal | Just |
    | interval | int | 0-12 | 7 |
    | vis_lissajous | float | 0-1 | 0.7 |
    | vis_particles | float | 0-1 | 0.7 |
    | vis_spectral | float | 0-1 | 0.7 |

    **Create DEMO_RECORDING.md** with step-by-step instructions:

    ```markdown
    # SolarDrone — Demo Recording Guide

    ## Goal
    Two 10-minute recordings: one during quiet solar conditions (Kp ≤ 2),
    one during active conditions (Kp ≥ 5). Should be audibly distinct.

    ## How to check current space weather
    - https://www.swpc.noaa.gov/products/planetary-k-index
    - Or watch the status overlay in SolarDrone: "live Kp X.X"
    - Quiet: Kp 0–2 (common, ~80% of days)
    - Active: Kp 5+ (occurs during geomagnetic storms, check alerts)

    ## Recording setup
    1. Launch SolarDrone Standalone
    2. Wait for status "live" (green, ~30s)
    3. Use your DAW or system audio recorder (Audacity, etc.)
    4. Record 10 minutes at default settings
    5. Note Kp value and timestamp

    ## What to listen for
    Quiet (Kp ≤ 2): sparse drone, few harmonics in L2, calm Lissajous
    Active (Kp ≥ 5): dense harmonic texture, turbulent particles, fast Lissajous morphing
    Storm (Kp ≥ 7): near-maximum L2 density, orange particles, chaotic Lissajous

    ## Suggested comparison clip
    Export 30-second segments from each recording. Place side-by-side.
    The contrast should be immediately perceptible even to a non-technical listener.
    ```
